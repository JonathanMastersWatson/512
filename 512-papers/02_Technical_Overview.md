# Technical Overview: 512 as a Constraint Layer

## Definition

512 is a **minimal execution-time constraint layer**.

It is not:
- a protocol
- a platform
- a runtime
- a control system

---

## Core Properties

512 is defined by being:
- minimal (512 bytes)
- non-ownable
- voluntary
- execution-adjacent
- enforcement-free

---

## Execution vs Settlement

A foundational distinction:

- **Execution** occurs locally, in real time
- **Settlement** records irreversible commitments

512 governs neither execution nor settlement.
It constrains the **legitimacy boundary** between them.

---

## Transparency and Continuity Principle
512-compatible systems must:
- produce Evaluation-Unavailable DENY when the gate cannot evaluate
- hold the commit boundary — execution does not proceed without admissibility established
- disclose the basis for any denial
- return authority to the human party on any adverse outcome
- not enforce compliance beyond the commit boundary decision
Failure must be disclosed, not concealed.

---

## Explicit Exclusions

512 does not include:
- identity
- permissions
- policy logic
- behavioral rules

Any system that does is not implementing 512.

---

## Technical Neutrality

512 is compatible with:
- multiple compute architectures
- multiple settlement rails
- multiple media systems

It mandates no stack choices.
